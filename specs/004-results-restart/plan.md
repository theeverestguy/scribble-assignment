# Implementation Plan: Results & Restart

**Branch**: `004-results-restart` | **Date**: 2026-06-03 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/004-results-restart/spec.md`

## Summary

Add round completion logic (auto-trigger when `submitGuess()` detects a correct answer), a "results" room status with a read-only results view showing the correct word, winner, scores, and guess history, and a host-only restart endpoint that clears all game state and returns all players to lobby while preserving the room, host, and player roster.

## Technical Context

**Language/Version**: TypeScript 5.x (Node.js 20+)

**Primary Dependencies**: Express 4.x, Zod 3.x, React 18, Vite 5

**Storage**: In-memory `Map<string, Room>` in `backend/src/services/roomStore.ts`. No databases.

**Testing**: Vitest (existing pattern in `roomStore.test.ts`, `schemas.test.ts`)

**Target Platform**: Node.js HTTP server (`localhost:3001`), React frontend (`localhost:5173`)

**Project Type**: Web application (Express backend + React/Vite frontend)

**Performance Goals**: Results view appears for all players within the 2-second polling window after a correct guess. Restart reflected in lobby within the polling window.

**Constraints**:
- No WebSockets/Socket.io — HTTP polling only (POL-1)
- No databases — in-memory only (MEM-1)
- No authentication (project constraint)
- Zod validation on all request payloads (VAL-1)
- TypeScript strict mode, no `any` (TS-1)

**Scale/Scope**: ~2–8 players per room, single-process Node.js server

## Technical Design

### Backend

#### 1. Model Changes (`models/game.ts`)

Extend `RoomStatus` type to include `"results"`:

```typescript
export type RoomStatus = "lobby" | "game" | "results";
```

No new interfaces needed — existing `RoomSnapshot` already contains `strokes`, `guesses`, `participants[].score`, and `secretWord`.

#### 2. Room Service Changes (`services/roomStore.ts`)

**`submitGuess()` — Add results transition on correct guess**:

After `room.guesses.push(guess)` and before `room.updatedAt = now()`:
```
if (isCorrect) {
  room.status = "results";
}
```

**`restartGame(code, participantId)` — New function**:

```
1. Get room from Map. If not found → return { error: "not-found" }
2. Validate: room.status === "results" → else { error: "not-results" }
3. Validate: participantId === room.hostId → else { error: "not-host" }
4. Reset game state:
   - room.status = "lobby"
   - room.currentRound = undefined
   - room.drawerId = undefined
   - room.currentWord = undefined
   - room.strokes = []
   - room.guesses = []
5. Reset each participant:
   - participant.score = 0
   - participant.hasScoredThisRound = false
   - participant.role = undefined
6. Update room.updatedAt
7. Save to Map
8. Return cloned room
```

Return type: `Room | { error: "not-found" | "not-results" | "not-host" }`
Add: `type RestartResult = Room | { error: "not-found" | "not-results" | "not-host" };`

**`toRoomSnapshot()` — Update secretWord visibility**:

Change line 278 from:
```typescript
secretWord: isViewerDrawer ? room.currentWord : undefined,
```
to:
```typescript
secretWord: (isViewerDrawer || room.status === "results") ? room.currentWord : undefined,
```

This reveals the secret word to ALL players when the room is in results state.

**Winner calculation** (client-side, but can be derived):
- The winner is the participant with the highest `score`.
- The frontend sorts `participants` by `score` descending and takes the first entry.
- In a single-round game, only the first correct guesser has 100 points; all others have 0.
- If all scores are 0, there is no winner (display "No winner" or "Nobody guessed correctly").

#### 3. Schema Changes (`api/schemas.ts`)

```typescript
export const restartSchema = z.object({
  participantId: z.string().uuid()
});
```

#### 4. Route Changes (`api/rooms.ts`)

New route on the existing `createRoomsRouter()`:

| Method | Path | Body | Success | Error |
|--------|------|------|---------|-------|
| POST | `/:code/restart` | `{ participantId }` | 200 `{ room }` | 404/403/400 |

Route handler:
```typescript
router.post("/:code/restart", (request, response, next) => {
  try {
    const { code } = roomCodeParamsSchema.parse(request.params);
    const { participantId } = restartSchema.parse(request.body);
    const result = restartGame(code, participantId);

    if ("error" in result) {
      switch (result.error) {
        case "not-found": throw new HttpError(404, "Room not found");
        case "not-host": throw new HttpError(403, "Only the host can restart");
        default: throw new HttpError(400, "Round has not ended yet");
      }
    }

    response.json({ room: toRoomSnapshot(result, participantId) });
  } catch (error) {
    next(error);
  }
});
```

**Existing route guards**: `appendStroke()`, `clearCanvas()`, and `submitGuess()` already check `room.status !== "game"` — these will naturally reject requests when status is `"results"` since `"results" !== "game"`. No changes needed to those guards.

### Frontend

#### 1. Type Updates (`services/api.ts`)

```typescript
export type RoomStatus = "lobby" | "game" | "results";
```

#### 2. API Method (`services/api.ts`)

```typescript
restartGame(code: string, participantId: string) {
  return request<{ room: RoomSnapshot }>(`/rooms/${encodeURIComponent(code)}/restart`, {
    method: "POST",
    body: JSON.stringify({ participantId })
  });
}
```

#### 3. Room Store (`state/roomStore.ts`)

```typescript
async restartGame() {
  const { room, participantId } = this.#session;
  if (!room) return;
  await api.restartGame(room.code, participantId);
  await this.fetchRoom();
}
```

#### 4. ResultsView Component (`components/ResultsView.tsx`) — NEW

- Receives props: `room: RoomSnapshot`, `viewer: Participant | null`
- Displays:
  - **Correct word**: `room.secretWord` (now visible to all players in results state)
  - **Winner**: Participant with highest `score` (sorted client-side), or "No winner" if all 0
  - **Scoreboard**: Sorted list of participants with scores (reuse logic from existing Scoreboard)
  - **Guess history**: Full chronological list from `room.guesses` with guesser name, text, correct/incorrect badge, and points
  - **Restart button**: Only visible if `viewer?.isHost === true`; calls `roomStore.restartGame()`
- No drawing or guessing controls
- Styled consistently with existing Card/button components

#### 5. GamePage Updates (`pages/GamePage.tsx`)

Add a conditional render based on `room.status`:

```typescript
if (room.status === "results") {
  return <ResultsView room={room} viewer={viewer} />;
}
```

This replaces the game view entirely with the results view. When the host restarts, polling updates `room.status` to `"lobby"`, and the existing lobby redirect logic returns players to the lobby screen.

### State Transitions

```
lobby ── host clicks "Start Game" ──▶ game
 game ── correct guess submitted ──▶ results
 results ── host clicks "Restart" ──▶ lobby
```

### Edge Cases & Error Handling

| Scenario | Handling |
|----------|----------|
| Non-host tries to restart | 403 — only host can restart |
| Restart called when status is not "results" | 400 — round has not ended |
| Player tries to draw/guess in results state | 400 — existing guards reject non-"game" status |
| Player joins during results | They see the results view (revealed word, scores, history) |
| All scores are 0 (nobody guessed correctly, round can't end) | Edge case noted in spec — round never reaches results; future feature may add manual end |
| Host refreshes during results | Polling restores results view — host identity preserved |
| Restart triggered, some players haven't polled yet | They see results until next poll, then get redirected to lobby |
