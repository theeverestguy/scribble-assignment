# Implementation Plan: Game Start & Drawer Flow

**Branch**: `002-game-start-flow` | **Date**: 2026-06-03 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/002-game-start-flow/spec.md`

## Summary

Enhance the existing game-start endpoint and in-memory store to assign roles (host=drawer, rest=guessers), select a secret word deterministically from the existing word list, store it server-side, and return role-filtered room snapshots so only the drawer sees the secret word.

## Technical Context

**Language/Version**: TypeScript 5.x (Node.js 20+)

**Primary Dependencies**: Express 4.x, Zod 3.x, tsx

**Storage**: In-memory `Map<string, Room>` in `backend/src/services/roomStore.ts`. No databases.

**Testing**: Vitest (existing pattern in `roomStore.test.ts`, `schemas.test.ts`)

**Target Platform**: Node.js HTTP server (`localhost:3001`)

**Project Type**: Web application (Express backend + React frontend, Vite dev server)

**Performance Goals**: Room snapshot served within the 2-second polling interval (existing baseline)

**Constraints**: 
- No WebSockets/Socket.io — HTTP polling only (POL-1)
- No databases — in-memory only (MEM-1)
- No authentication (project constraint)
- Zod validation on all request payloads (VAL-1)
- TypeScript strict mode, no `any` (TS-1)

**Scale/Scope**: Single-process Node.js server, ~2–8 players per room

## Technical Design

### Backend

#### 1. Model Changes (`models/game.ts`)

Add `role` to `Participant`:

```typescript
export type ParticipantRole = "drawer" | "guesser";

export interface Participant {
  id: string;
  name: string;
  isHost: boolean;
  role: ParticipantRole;    // NEW — assigned on game start
  joinedAt: string;
}
```

Add game fields to `Room`:

```typescript
export interface Room {
  code: string;
  status: RoomStatus;
  participants: Participant[];
  hostId: string;
  currentWord: string;       // NEW — secret word for current round
  drawerId: string;          // NEW — participant ID of the drawer
  currentRound: number;      // NEW — 0-based round counter
  createdAt: string;
  updatedAt: string;
}
```

Update `RoomSnapshot`:

```typescript
export interface RoomSnapshot {
  code: string;
  status: RoomStatus;
  participants: Participant[];     // each with role now populated
  hostId: string;
  currentRound: number;            // NEW
  secretWord?: string;             // NEW — only present for drawer
  availableWords: string[];        // kept for future UI use
  roles: ParticipantRole[];        // kept for future UI use
}
```

#### 2. Room Service Changes (`services/roomStore.ts`)

**Enhanced `startGame(code, participantId)`**:

```
1. Validate: room exists, caller is host, >= 2 players  (existing)
2. Select word: `STARTER_WORDS[0 % STARTER_WORDS.length]`  (round 0)
3. Assign roles:
   - Set host participant.role = "drawer"
   - Set all other participants.role = "guesser"
4. Set room.currentWord = selected word
5. Set room.drawerId = hostId
6. Set room.currentRound = 0
7. Set room.status = "game"
8. Save and return cloned room
```

**Enhanced `toRoomSnapshot(room, viewerParticipantId?)`**:

```
1. Start with base snapshot (participants, code, status, etc.)
2. Determine viewer's role from room participants by viewerParticipantId
3. If viewer is drawer:
   - Include secretWord = room.currentWord
4. If viewer is guesser or no viewerParticipantId:
   - Omit secretWord (undefined)
5. Include currentRound from room
6. Return snapshot
```

**Pure word selection function** (new, to satisfy IMM-1):

```typescript
export function selectWord(wordList: readonly string[], round: number): string {
  return wordList[round % wordList.length];
}
```

#### 3. Route Changes (`api/rooms.ts`)

No new routes needed. The `POST /:code/start` return value automatically benefits from the enhanced `toRoomSnapshot`. The `GET /:code` endpoint already passes `participantId` query param, so it also returns role-filtered results.

#### 4. Existing `toRoomSnapshot` Gap

The `viewerParticipantId` parameter is already present in the function signature but currently ignored. This plan activates it.

### Frontend

#### 1. Type Updates (`services/api.ts`)

Add `secretWord?: string` and `currentRound: number` to `RoomSnapshot` interface.

#### 2. Game Page (`pages/GamePage.tsx`)

- Determine viewer's role from `room.participants` using `participantId`
- If `role === "drawer"`: show the secret word prominently, hide GuessForm, show canvas placeholder
- If `role === "guesser"`: hide secret word, show GuessForm, show canvas placeholder
- Add role badge next to player name in the player info card
- Round display: use `room.currentRound` from snapshot

### Edge Cases & Error Handling

| Scenario | Handling |
|----------|----------|
| Game start with <2 players | Already blocked by existing validation (403) |
| Non-host tries to start | Already blocked by existing validation (403) |
| Poll during game-start transition | Snapshot returns status "game" once; lobby-to-game redirect handles it |
| Empty word list | Defensive: selectWord should have a guard, but spec assumes >= 1 word |
| Player re-joins after game started | Spec says joining is lobby-only; no rejoin mechanism needed |
| Snapshot requested without participantId | secretWord is omitted (safe default) |

### Testing Plan

**Backend unit tests** (in `roomStore.test.ts`):
- `startGame` with host + players assigns drawer role to host, guesser roles to others
- `startGame` selects word deterministically (same config = same word)
- `toRoomSnapshot` includes secretWord for drawer
- `toRoomSnapshot` omits secretWord for guesser
- `toRoomSnapshot` omits secretWord when no participantId given
- `selectWord` pure function wraps correctly at word list boundary

**Frontend component tests** (in `api.test.ts` or new):
- GamePage renders secret word for drawer role
- GamePage hides secret word for guesser role
